# 데이터와 구현 계약

## 1 기술 방향

사용자가 지정한 Godot 엔진을 사용하며 PC 네이티브 실행을 우선한다. 1차 구현 기준은 Godot 4.7.2와 GDScript다. 화면과 입력은 Control·Container·Theme, 규칙은 화면에 의존하지 않는 시뮬레이션 모듈, 콘텐츠는 버전이 있는 JSON 데이터로 분리한다. 기존 웹·TypeScript 구현안은 이 엔진 결정으로 대체한다.

시뮬레이션은 씬 트리·프레임 속도·현실 시간에 의존하지 않는다. UI는 명령을 전달하고 결과와 상태를 읽는다. 자동 진행은 주마다 프레임을 양보해 중단과 화면 갱신을 처리한다. 대규모 세계의 실행 비용이 측정 기준을 넘을 때만 작업 스레드 분리를 추가한다. 공통 UI 스타일은 Godot Theme로 관리한다. [Godot Theme](https://docs.godotengine.org/en/stable/classes/class_theme.html)

저장은 Godot FileAccess의 사용자 데이터 경로를 사용한다. 회차·메타·결산 영수증을 하나의 스냅숏으로 묶고 임시 파일 작성·검증·교체와 이전 세대 보존으로 일관성과 복구를 확보한다. JSON 기반 저장의 정수·실수 복원과 필수 필드·콘텐츠 ID 검증을 수행한다. [Godot FileAccess](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html)

이 문서는 본편의 구현 계약이다. 현재 작성한 1차 52주 플레이 빌드의 실제 기능과 단순화는 게임 폴더 `godot/README.md`를 기준으로 구별한다. 전체 제작은 08번의 단계와 검증 기준을 따른다.

| 계층 | 책임 | 할 수 없는 일 |

| 명령 검증 | 자격·재고·계약·일정 검증, 예약 | UI 표시만 보고 상태 수정 |
| 시뮬레이션 | 한 주 처리, 난수, 결과와 원장 | 실제 시계나 네트워크 의존 |

| 저장 | 버전·체크섬·복구·원자적 커밋 | 출처 불명 데이터 실행 |
| 연동 | 사람이 읽는 요약, 검증된 자유 모드 가져오기 | 기본 회차 임의 덮어쓰기 |

파일 구조는 시뮬레이션·명령·콘텐츠·화면·저장·검증의 책임으로 분리한다. 현재 프로젝트는 `sim`, `content`, `ui`, `tests`, `assets`를 사용한다. 폴더 이름보다 참조 방향을 지킨다. 경제 시뮬레이션은 씬 트리·저장소·현재 시각에 의존하지 않는다.

원장에서는 금전 계정과 물자 계정을 구별한다. 생산은 입력 재고 차감·변환 계정·출력 재고 증가, 소비는 해당 재고→소비 계정, 손실은 재고→손실 계정으로 남긴다. 돈과 식량을 같은 숫자로 합쳐 자산 보존을 검증하지 않는다.

## 4 한 주 처리의 고정 순서

한 주의 명령은 초안에서 모은 뒤 전체 검증한다. 실행 불가 명령이 있으면 해당 명령과 충돌 원인을 반환하고 아직 턴을 진행하지 않는다. 플레이어가 수정을 확정하면 한 번 커밋한다.

1. 현재 주의 명령·일정·법·계약을 검증하고 자원을 예약한다.
2. 계절·날씨·기존 위험 상태를 갱신하고 해당 주 시작 사건 효과를 적용한다.
3. 이전 주 출발 운송의 이동과 도착을 처리한다. 도착품은 이번 주 공정 입력에 사용 가능하다.
4. 기한 계약·예약 출하를 처리하고 새 운송을 출발시킨다. 같은 주 출발과 도착은 불가다.
5. 가용 노동을 확정한다. 파종·수확·구호·군사·공사·산업 우선순위를 적용한다.
6. 공정별 입력 스냅숏으로 생산을 동시에 계산한다. 새 중간재는 다음 주부터 생산에 사용한다.
7. 건설·개간·연구·훈련을 진행한다. 이번 주 완성 시설은 다음 주부터 운영한다.
8. 민간·공공·부대 식량 배분과 소비, 물·주거·난방 충족을 처리한다.
9. 저장 부패·시설 피해·노선 위험·자원 고갈을 처리한다.
10. 급여·세금·이자·시설 유지비·공납을 처리한다. 예약 금액과 실제 지급의 차이를 해제한다.
11. 건강·출생·사망·이주를 처리한다. 새 인구는 다음 주 노동과 소비에 포함한다.
12. 이동 후 동일 전장 부대의 교전·퇴각·포로·손실을 처리한다. 해당 주 식량은 이미 소비한 것으로 본다.
13. 정치 태도·외부 AI·직무 피로·관계 약속·서사 조건을 평가한다.
14. 이정표·특전 제시·주 과업·시험·회차 종료를 평가하고 다음 주 사건 대기열을 만든다.
15. 원장·결과·난수 카운터·주 번호를 저장하고 UI에 요약을 반환한다.

같은 우선순위의 동시 주문은 주문 생성 순서, 동률이면 고유 ID 순서다. 자원 부족 노동 배치는 사용자 우선순위→필수 소비→안정된 ID 순서로 결정하고 화면에서 순서를 보여 준다. 프레임 속도나 객체 순회 우연에 영향을 받지 않는다.

## 5 난수와 재현

난수는 고정된 32비트 정수 알고리즘 xoshiro128**를 구현 계약으로 지정한다. 시스템별 독립 스트림은 세계 생성·기후·외교·전투·사건·특전 6개다. 시드 파생 규칙과 테스트 벡터를 엔진 구현 시 함께 고정한다. 원장·미리보기·화면 열기는 난수를 소비하지 않는다.

같은 저장·같은 명령이면 같은 결과여야 한다. 전투 미리보기는 난수를 미리 굴리지 않고 가능한 범위만 계산한다. 결과는 명령 커밋 시 확정한다. 저장 불러오기나 대사 창을 열고 닫는 것으로 특전 후보가 바뀌지 않는다. 새로고침은 명시 명령이며 횟수와 새 후보를 같은 트랜잭션으로 저장한다.

## 6 데이터 정의의 필수 항목

| 데이터 | 필수 항목 | 검증 |
|---|---|---|
| 시설 | id, localizationKey, tier, prerequisites, construction, staffing, capacity, recipes, maintenance | 비용 음수 금지, 선수 존재, 용량 단위 |
| 기술 | id, prerequisites, work, money, materials, experiment, unlocks | 선수 순환 금지, 접근 불가능 해금 탐지 |
| 특성·특전 | id, tags, effects, exclusions, eligibility, caps, lifetime | 배타 충돌, 중복·무한 배율 금지 |
| 사건 | id, trigger, exclusions, priority, cooldown, expiry, participants, options | 모든 상태에 실행 가능한 선택지 1개 |
| 선택지 | id, requirements, immediateEffects, commitments, followups, text | 비용·기한·후속 ID 존재 |
| 헌장 | id, startStateTemplate, objectives, regions, crisisPool, duration, rewards | 식량·경로·필수 자원 가능성 |
| 메타 노드 | id, cost, prerequisites, sealRequirements, startEffects | 총비용·전제 순환·중복 구매 |

효과 언어는 `addResource`, `transferResource`, `addMoney`, `createContract`, `changeAttitude`, `startProject`, `setFlag`, `scheduleEvent`, `grantTrait`, `queuePerkDraft`, `recordDiscovery` 같은 허용 명령으로 제한한다. 임의 JavaScript·URL·HTML을 데이터에서 실행하지 않는다. 계산식은 검증된 파라미터와 등록된 공식 ID만 참조한다.

`addResource`는 출처를 요구한다. 생산·보상·외부 지원·효율 보너스 중 하나를 기록한다. 공공과 주민 재고 사이 이동에는 `transferResource`만 허용한다. 같은 사건의 결과 적용 키는 `eventInstanceId + optionId`로 한 번만 처리한다.

## 7 저장과 복구

슬롯은 수동 20개, 회차별 자동 최근 3개, 계절 시작 4개를 기본으로 한다. 메타 프로필과 각 회차를 분리하고 삭제 전 어느 데이터가 사라지는지 표시한다. 회차 삭제는 이미 얻은 정당한 공훈과 도감을 지우지 않는다. 프로필 초기화는 별도 작업이다.

결산은 **회차 상태 finalized + 공훈 증가 + 해금 + 영수증 생성**을 같은 저장 스냅숏으로 처리한다. 새 파일 검증이 완료되기 전 이전 정상 세대를 유지한다. 도중에 앱이 닫히면 전체가 반영된 스냅숏 또는 이전 정상 스냅숏으로 복구한다. UI 재진입 시 영수증을 확인하고 보상 창만 다시 보여 줄 수 있다. 본편에서 결산 후 장기 통치로 전환한 저장에는 `metaRewardEligible=false`를 고정한다.

공훈 자격과 발견 자격을 구별해 `metaRewardEligible`, `discoveryEligible`, `officialSealEligible`를 별도로 저장한다. 정상 장기 통치는 뒤의 두 값만 true다. 자유 모드와 외부 가져오기는 세 값 모두 false다. 발견·인장 등록도 고유 키로 중복 처리하지 않으며 공훈 영수증을 새로 만들지 않는다.

저장 파일은 JSON을 기본으로 하고 schemaVersion, rulesVersion, contentVersion, createdAt, payload, checksum을 가진다. 압축은 사용자 파일 크기가 커질 때 추가하되 형식 버전을 바꾼다. 읽기 성공 전 기존 저장을 덮어쓰지 않는다. 해시 검증은 손상 탐지용이며 사용자 수정을 보안 공격으로 간주하지 않는다.

마이그레이션은 구버전→다음 버전의 순차 변환이며 이전 파일 백업을 유지한다. 삭제된 콘텐츠 ID는 대체 규칙이나 보상으로 치환한다. 호환 불가 파일은 이유와 지원 버전을 알려 주고 원본을 보존한다. 데이터 모드로 변경한 회차는 자유 모드로 분리한다.

## 8 캐챗 연동

기본 기능은 「치세 정보 복사」다. 영주·영지·주·단계·작위·인구·금고·공공 및 총식량·세력·진행 사업·인물 관계·최근 사건·현재 약속을 사람이 읽을 수 있는 텍스트로 내보낸다. 게임 날짜는 절대 주와 계절 주를 함께 기록한다. 전송 자체는 사용자가 붙여넣기할 때 이루어진다.

기존 이미지 체계 `ern/b/`, `ern/c/`는 자산 매핑의 입력일 뿐 데이터 ID가 아니다. 인물 대응은 04번 2장 표로 고정한다(CH01=A, CH02=B, CH03=C, CH04=D, CH05=F, CH06=G, CH07=I, CH08=H, CH09=E, CH10=J, CH11=L, CH12=K). 캐챗 정보창 원문 형식과의 호환 프로필은 나중에 연결하며, 그 전까지는 게임 독립 정보창을 내보낸다.

가져오기는 텍스트→파싱→필드별 비교→충돌 표시→자유 모드 복사본 생성의 순서다. 자산·관계·날짜를 읽었더라도 없는 시설·연구·혈연을 멋대로 생성하지 않는다. 한도를 넘는 인구·음수 재고·미성년 로맨스·알 수 없는 ID는 오류로 표시한다. 원래 회차와 메타 재화는 변경하지 않는다.

## 9 성능과 규모 예산

| 항목 | 출시 검증 목표 |
|---|---|
| 지원 세계 크기 | 16권역, 48거점, 직할 12곳, 시설 2,000개 |
| 일반 주민 | 최대 합계 200,000명, 집단 최대 1,000개 |
| 명명 인물 | 활성 최대 200명, 지난 인물은 연대기 요약 |
| 계약·사업 | 활성 계약 300개, 사업 100개 |
| 한 주 처리 | 기준 PC에서 95백분위 300ms 이하 |
| 13주 자동 진행 | UI 응답 유지, 전체 3초 목표, 중단 신호 100ms 이내 수용 |
| 초기 조작 가능 | 로컬 캐시 없이 보통 광대역에서 5초 목표 |
| 회차 저장 | 비압축 10MB 목표, 상한 30MB 경보 |

성능 수치는 실측 결과가 아닌 목표다. 기준 기기는 구현 단계에서 CPU·메모리·GPU·Godot 버전을 기록한다. 매주 전체 대사를 저장하지 않고 사건 ID·선택·변수만 저장한다. 오래된 원장은 계절별 요약과 감사 가능한 합계로 압축하되 주요 사건과 계약 원문은 보존한다.
