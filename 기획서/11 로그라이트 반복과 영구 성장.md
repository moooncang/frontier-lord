# 로그라이트 반복과 가문 강화

기준일: 2026-11-18. 이 문서는 현재 Godot 본편의 구현과 콘텐츠 데이터를 기준으로 한다. 이전 초안의 장기 통치 구상은 마지막 절에만 미구현 항목으로 남긴다.

## 1. 현재 구현 범위

한 통치는 **52주**다. 부임 준비에서 영주·영지·부임 물자를 정하고, 해금한 지원 물자 1개와 가문 방침 최대 2개를 선택한다. 운영 중 시설 개발, 작업 방침, 사건 선택, 특전과 성물 조합으로 계절 목표와 겨울 시련을 준비한다. 통치가 끝나면 성과에 따라 공훈을 받고, 가문 강화를 구매해 다음 통치를 준비한다.

| 구분 | 구현 수량·규칙 |
|---|---|
| 가문 특성 | 6계열 48종: 기반 강화 24종·선택권 해금 12종·가문 방침 12종 |
| 공통 강화 | 기존 M 계열 강화 8종. 가문 특성과 합쳐 총 56개 구매 항목 |
| 가문 방침 | 해금한 12종 중 최대 2개 선택. 장점과 대가를 함께 적용 |
| 지원 물자 | 해금한 6종 중 최대 1개 선택. 새 통치 시작에 한 번 지급 |
| 부임 물자 | 별도 선택 예산을 사용하는 준비품 6종. 기본 예산 3, M20과 LD06으로 최대 5 |
| 특전 | 전체 정의 96종. 이번 통치에 획득한 특전만 적용 |
| 성물 | 전체 정의 48종. 이번 통치에 실제 장착한 최대 3개만 적용 |
| 운영 조합 | 성물과 특전을 연결하는 12종. 조건을 충족하면 자동 활성화 |
| 계절 지원 | 12종. 각 계절 3종 제안 중 1종을 구매해 기간 효과 적용 |
| 판타지 협약 | 6계열 중 회차마다 3계열 발견·최대 2계열 채택. 전용 건물 18종·연속 사건 30개 |
| 개척 난도 | 기본 0단계와 추가 1~5단계. 성공 완주로 순차 해금 |

콘텐츠 수량은 전체 정의 기준이다. 실제 제안은 회차 규칙, 등장 주차, 이미 획득·제외한 항목에 따라 달라진다. 기존 저장에는 기존 규칙을 유지하며, 새 콘텐츠를 보유 목록에 일괄 지급하지 않는다.

## 2. 통치 흐름과 적용 시점

| 단계 | 플레이어 행동 | 적용 결과 |
|---|---|---|
| 가문 강화 | 공훈으로 기반 강화·선택권·방침을 구매 | 프로필에 습득 기록 저장 |
| 가문 방침·지원 선택 | 해금한 방침 최대 2개, 지원 물자 최대 1개, 첫 특전·성물 계열 지정 | 다음 부임의 선택을 저장 |
| 영주 선택 | 제시된 후보의 장점·약점을 비교 | 선택한 영주의 시작 조건 적용 |
| 영지 선택 | 지역 이점, 환경 조건, 겨울 시련 확인 | 이번 통치의 지역과 위험 조건 확정 |
| 부임 물자 선택 | 현재 물자 예산 안에서 준비품 선택 | 지원 물자와 별도로 적용 |
| 통치 시작 | 첫 특전 3개 중 1개 선택 | 가문 특성·방침·지원 선택의 스냅숏 생성 |
| 주간 운영 | 건설 승인·작업 방침·주 진행·결과 확인 | 실제 비용·생산·공사·사건 결과 반영 |
| 계절 평가 | 13·26·39·52주 목표 확인 | 물자는 즉시, 공훈은 최종 결산 때 지급 |
| 결산 | 성공·패배·중도 종료 결과 확인 | 회차별 지급 기록을 남기고 공훈 정산 |
| 다음 통치 | 공훈 사용 또는 재분배 후 새 준비 선택 | 새 스냅숏으로 다시 시작 |

가문 특성 구매·재분배와 방침·지원 선택 변경은 진행 중인 통치를 마친 뒤 가능하다. 현재 통치의 효과를 프로필 변경으로 다시 계산하지 않는다. 지원 물자와 방침의 시작 자원은 부임 시 한 번만 지급하며, 불러오기나 화면 재진입으로 반복 지급하지 않는다.

### 2.1 52주 목표

| 평가 주 | 계절 목표 | 달성 공훈 |
|---|---|---:|
| 13주 | 농지 6구획 확보 | 3 |
| 26주 | 곡물 곳간 완공 | 3 |
| 39주 | 예고된 겨울 난방량 확보 | 4 |
| 52주 | 연간 목표와 겨울 시련 완료 | 6 |

최종 성공은 52주 완주, 생존 주민 존재, 농지 6구획·곡물 곳간 1개·정상 배급 기준 식량 13주분, 선택된 겨울 시련 통과를 모두 요구한다. 계절 목표 미달이 곧바로 게임 종료를 의미하지는 않으며, 공개된 피해를 반영하고 다음 운영으로 이어진다. 중도 종료는 완주 성공으로 처리하지 않는다.

### 2.2 공훈 지급

13주를 처리한 통치부터 지급 대상이다. 저장 상태의 주차는 다음 처리 주를 가리키므로 내부 판정은 `state.week > 13`이다. 13주 미만 종료는 공훈을 지급하지 않고 첫 기록 보너스도 소모하지 않는다.

| 항목 | 현재 지급 규칙 |
|---|---|
| 기본 목표 | 농지·곳간·식량 목표를 결산 시 충족한 항목당 6 |
| 성공 완주 | 최종 성공 시 10 |
| 첫 기록 | 공훈 지급 대상인 첫 결산에 8, 프로필당 한 번 |
| 계절 생존 | 처리한 13주마다 2, 최대 8 |
| 겨울 시련 | 최종 시련 통과 시 6 |
| 계절 목표 | 달성한 계절 목표의 공훈 합계, 최대 16 |
| 계약 | 실제 완료 기록이 있는 계약당 3. 해당 규칙을 사용하는 저장에 적용 |
| 영지 발전 | 인구 증가·승격·시설 다양성·습격 격퇴·민심·건강의 합계 |

영지 발전은 주민 80명 초과분 5명당 1(최대 8), 승격 점수 누적(촌락 5·마을 추가 7), 임시 시설을 제외한 운영 시설 3종당 1(최대 6), 습격 격퇴당 1(최대 3), 민심 60 이상 2, 건강 60 이상 2로 계산한다. 결산 화면은 실제 지급 항목과 합계를 표시한다. 이전 초안의 고정 최대 50점이나 별도 업적 인장 지급 규칙을 적용하지 않는다.

## 3. 무엇이 남는가

| 다음 통치에도 보존 | 해당 통치에서 다시 구성 |
|---|---|
| 사용하지 않은 공훈 | 금고·식량·자재·주민·시설·공사 |
| 가문 특성 습득 단계와 공통 강화 8종 구매 기록 | 실제 획득한 특전과 성물, 장착 조합 |
| 다음 부임에 고른 방침·지원 물자·계열 지정 | 사건 진행, 인물 관계, 작업 방침, 위기 대비 |
| 특전·성물 발견 기록과 통치 기록 | 물자 주문, 현재 주차, 새로고침·제외 잔여 횟수 |

발견 기록은 도감 열람 기록이다. 발견한 성물을 다음 통치에 자동 장착하거나 이전 특전을 계속 적용하는 권리는 아니다.

## 4. 가문 특성 48종

각 계열은 기반 강화 4종, 선택권 2종, 가문 방침 2종으로 구성한다. 선행조건은 표시된 항목의 **1단계 습득**이며, 선행 항목을 최대 단계까지 올릴 필요는 없다. 비용의 `2 / 4 / 6`은 각 단계의 추가 구매 비용이고 누적 비용이 아니다.

### 4.1 기반 강화 합산

같은 기반 특성의 단계는 선형 합산한다. 예를 들어 시설 회계 3단계는 유지비 −12%다. 서로 다른 출처의 배율은 각 효과가 연결된 계산 경로에서 곱하고, 세금 수금률·신뢰 효과·겨울 채집률처럼 가산형으로 정의된 값은 합산한다. 영구 생산·소비 배율은 실제로 존재하며, 이전 초안의 ‘상시 배율 0%’ 제한은 현재 규칙이 아니다.

목표치 효과는 건강·민심·치안을 즉시 해당 수치만큼 더하는 보상이 아니다. 주간 상태 계산에 사용하는 목표치를 바꾼다. 공사 작업량 배율은 새로 착공하는 공사에 적용하며, 이미 진행 중인 공사의 남은 작업량을 재계산해 줄이지 않는다.

### 4.2 무료 재분배

통치가 진행 중이지 않을 때 ‘무료 재분배’를 사용하면 가문 특성 48종에 실제 사용한 공훈을 전액 돌려받는다. 가문 특성 습득 단계와 선택한 가문 방침·지원 설정은 해제된다. 공통 강화 8종의 구매 기록과 구매 비용은 이 재분배 대상에서 제외한다. 재분배 후 다시 구매·선택한 내용은 다음 통치의 새 스냅숏에 반영한다.

## 6. 가문 방침 12종

방침은 공훈으로 해금해도 자동 적용되지 않는다. 다음 부임에 사용할 방침을 최대 2개 선택해야 한다. 두 칸이 차 있으면 기존 방침 하나를 지정해 교체한다. 선택 해제나 교체는 해금 기록을 지우거나 공훈을 다시 요구하지 않는다. 같은 방침을 두 칸에 중복 선택할 수 없다.

## 8. 특전·성물·운영 조합

특전 96종은 네 계열(농업·보존·생산·행정), 성물 48종은 세 계열(풍요·공방·수호)로 분류한다. 특전은 제안된 3개 중 1개를 고르고, 성물도 획득 제안에서 1개를 선택한다. 이미 습득한 특전과 이번 통치에서 제외한 특전은 적격 후보에서 빠진다. 주차 제한이 있는 효과는 해당 기간에만 제안한다.

성물은 보유와 장착을 구별한다. 성소에 최대 3개까지 장착하며, 보관만 한 성물은 생산·소비 효과나 조합 판정에 포함하지 않는다. 같은 계열의 특전 묶음, 성물 묶음, 성물과 특전을 연결한 운영 조합은 서로 다른 규칙이다.

운영 조합은 **지정된 두 성물 중 최소 1개를 실제 장착하고, 지정 계열 특전을 2개 이상 보유**하면 활성화된다. 기존 특전도 계열 개수에 포함한다. 두 연결 성물을 모두 장착해도 같은 운영 조합을 두 번 적용하지 않는다.

### 10.1 판타지 협약으로 달라지는 한 통치

판타지 협약은 가문 강화의 구매 항목을 늘리는 대신, 이번 통치에 지을 시설과 운영 부담을 바꾼다. `config.fantasy:true`인 새 통치는 정령숲·화룡·달빛 수로·태엽 골렘·황혼·별의 학당 여섯 계열 중 서로 다른 세 계열을 8·14·20주부터 발견한다. 한 번의 통치에는 최대 두 계열을 채택하며 거절한 방향을 같은 회차에서 다시 뽑지 않는다. 발견 계획은 기존 사건·특전 난수와 독립적으로 정해 저장한다.

각 계열은 **채택 → 첫 시설 완공·운영 분기 → 둘째 시설 완공·문제 대응 → 2주 뒤 최종 허가 → 셋째 시설 완공·보상**의 다섯 사건을 가진다. 전용 시설은 총 18종이고 계열마다 앞의 두 시설은 A등급, 마지막 시설은 B등급이다. 기본 공사 묶음은 계열당 20금과 자재·40인주이며, 실제 비용·작업량은 적용 중인 규칙과 가문·회차 효과에 따라 달라진다. 사건의 협약비·안전 정비 비용은 공사비와 별도다.

| 계열 | 첫 분기 | 다른 분기 | 완성 시설 |
|---|---|---|---|
| 정령숲 협약 | 정령과 공존: 식량 생산과 숲 보존 | 집중 재배: 채소·수확과 급여 부담 | 세계수 정원 |
| 화룡 공생 | 온기 공유: 난방 절감과 유지비 | 용열 산업: 도구·벌목과 도구 소모 | 화룡 대화로 |
| 달빛 수로 | 주민 물길: 채집·저장과 난방 | 상단 운하: 구매·저장과 급여 | 조수 성소 |
| 태엽 골렘 | 정비 우선: 도구 절약과 생산 감소 | 연속 가동: 채석·도구 생산과 유지비 | 자동공방 |
| 황혼의 서약 | 망령 안식: 보관·치안과 채집 감소 | 수호 서약: 위협 억제·치안과 건강 | 황혼 파수탑 |
| 별의 학당 | 관측과 보존: 저장·도구 절약과 유지비 | 공허 재배: 채소·구매와 난방 | 천구 도서관 |

선택한 분기는 회차 수치에 한 번 합성하고 생산 건물은 주민·원료를 실제로 사용한다. 기존 특전과 성물의 생산 효과도 해당 시설에 연결된다. 지정 성물 계열을 장착하거나 지정 특전 계열을 2개 갖추면 일부 사건 비용을 대신하는 선택을 할 수 있으며, 장착품·특전 자체를 소모하지 않는다. 별도의 마력 화폐나 매주 눌러야 하는 수령 버튼을 만들지 않는다.

모든 협약 사건은 확정 무료 대안을 가진다. 최종 공사는 48주까지 허가할 수 있고 보류하면 앞선 시설·분기 효과를 유지한다. 완성 시 성물 또는 계열별 물자 중 하나를 받으며 52주 진입 이후의 완공은 물자를 자동 정산한다. 재선택·재장착·저장 복원으로 단계나 보상을 반복 적용하지 않는다. 다음 통치에서는 다시 발견하며 가문 강화 48종·공통 강화 8종의 보유 내역을 변경하지 않는다.

`state.fantasy`가 없는 기존 회차는 새 발견·시설·효과를 받지 않는다. 신규 검증은 여섯 계열의 두 분기를 실제 주 진행으로 완성하는 기능 검증과, 실제 시작 자원으로 투자·식량·장작을 관리하는 경제 주행을 구분한다. 최종 시설을 지었다는 사실과 연말 목표를 성공했다는 사실은 서로 다른 결과다.

## 12. 후속 확장 — 미구현

8년 기본 통치와 6·10년 변형, 시작 헌장 8종 선택, 장기 통치·계승 모드, 업적 인장, 현재 개척 난도와 별개의 도전 모드 10단계, 별도 시작 유산 24종은 이전 초안의 후속 구상이다. 현재 본편의 기능·성공 조건·보상 수량에 포함하지 않는다. 과거의 24개 가문 강화 목록과 ‘상시 영구 배율 0%’ 원칙도 현재 구현을 설명하는 규칙으로 사용하지 않는다.

향후 이 기능을 도입하려면 현재 52주 경제·저장·보상 규칙과의 연결을 별도로 설계하고 구현해야 한다.
